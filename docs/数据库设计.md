# 数据库设计

SQLite 单文件数据库，7 张表：`user`、`item`、`favorite`、`message`、`trade_order`，以及索引。

## user 用户

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| username | TEXT | 唯一，3—20 位字母数字下划线 |
| nickname | TEXT | 昵称 |
| password_hash | TEXT | pbkdf2/scrypt 加盐哈希，绝不明文 |
| role | TEXT | user / admin |
| created_at | TEXT | 创建时间 |

## item 商品

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER | 主键 |
| title | TEXT | 2—60 字 |
| description | TEXT | 描述，≤500 字 |
| price | REAL | CHECK (price > 0) |
| category | TEXT | 图书教材/电子数码/生活用品/服饰鞋包/运动器材/其他 |
| condition | TEXT | 全新/几乎全新/轻微使用/明显使用 |
| image | TEXT | 原图相对路径，最长边 ≤1600px |
| thumb | TEXT | 480px 缩略图，列表页只加载它 |
| status | TEXT | pending/approved/rejected/offline/sold |
| seller_id | INTEGER | 发布者，外键 user.id |
| review_note | TEXT | 审核说明或驳回原因 |
| created_at / updated_at | TEXT | 时间戳 |

索引：`(status, created_at DESC)` 支撑首页与分页；`(category, condition)` 支撑两维筛选；`title` 支撑关键词查询。

## favorite 收藏

`(user_id, item_id)` 联合主键，天然去重；`created_at` 记录收藏时间。

## message 留言

| 字段 | 说明 |
| --- | --- |
| item_id | 所属商品 |
| user_id | 留言人 |
| parent_id | 被回复的留言 id，顶层留言为 NULL，只允许两层 |
| content | 1—300 字 |

## trade_order 订单

| 字段 | 说明 |
| --- | --- |
| item_id / buyer_id / seller_id | 商品、买家、卖家 |
| status | pending/confirmed/completed/cancelled |
| created_at / updated_at | 时间戳 |

## 订单状态机

```
pending(待确认) --confirm(卖家)--> confirmed(已确认) --complete(买家)--> completed(已完成)
      |                                    |
      +-------------cancel(买卖双方)-------+--> cancelled(已取消)
```

- `completed`、`cancelled` 为终态，任何动作都被拒绝。
- 状态迁移用白名单字典实现：`TRANSITIONS = {当前状态: {动作: 目标状态}}`，不在表里的动作一律拦截。
- 动作与角色绑定：`confirm` 只能卖家、`complete` 只能买家、`cancel` 双方都可。

## 并发与一致性

- 下单前检查是否已有 `pending/confirmed` 订单，避免一物多卖。
- 完成订单时把商品置为 `sold`；订单取消后商品恢复在售。
- 所有写操作单事务提交，异常回滚。
